# 银枢 · AI银行副驾（YinShu AI Banking Copilot）

> 面向"银行AI智能体"比赛的**可本地运行、可现场演示**系统。
> 评审核心：**安全 + 体验**。用户用自然语言表达金融意图，Agent 自主完成
> **意图理解 → 任务规划 → 调用银行工具执行 → 结果反馈**，并驱动一个仿真手机银行界面实时联动。

**当前进度：阶段 1~6 + 赛题对齐阶段全部完成（selftest 312/312、verify 20/20、彩排 25/25、赛题对齐专项 26/26）**，详见 [阶段进度](#七阶段进度)。

一键验收：`npm run selftest` / `npm run verify` / `npm run rehearsal`（详见 [自测清单](docs/自测清单.md)）。

**赛题对齐要点：** 三级权限（🟢自动 / 🟡确认 / 🔴多因子，转账按**当日累计 ≤¥1,000** 分档）、注入防御、异常熔断、完整决策链路审计、任务 DAG 拆解、无动态代码执行的沙箱声明。

- 阶段 1：骨架 + 模拟数据 + 对话/工具框架 + 全程留痕 + 风控规则引擎
- 阶段 2：智能转账 / 定时转账 / AA 拆分收款 / 撤销转账 + 二次确认（含短信验证码）
- 阶段 3：账单分析 + 评分制异常识别 + 订阅自动识别与一键取消
- 阶段 4：风险测评 / 适当性拦截 / 推荐对比 / 申购赎回（含风险提示朗读）+ 卡片申请/额度/限额/挂失
- 阶段 5：跨场景联动（一句话→锁定资金→鲜花蛋糕预订→提醒）+ UI 打磨 + 异常兜底

**25 个工具全部实现**（现已扩展至 **27 个**，新增交易密码修改、卡片解挂），无任何占位工具。验证方式见 [验收方法](#五验收方法)。

## 一、快速开始

```bash
# 1. 进入项目目录
cd yinshu-banking-agent

# 2. 安装依赖（本项目零第三方依赖，秒过；仅为满足标准流程）
npm install

# 3. 启动
npm start
```

浏览器打开 **http://127.0.0.1:8787** 即可。

其他命令：

```bash
npm run selftest   # 自测：数据完整性 + 工具 + Agent 编排（阶段验收用）
npm run reset      # 恢复演示初始数据
```

> 要求 Node.js ≥ 18（本机已验证 v24.19.0）。**无需数据库、无需网络、无需 API Key** 即可完整演示。

### 大模型模式（可选）

默认使用**本地意图引擎**（离线演示模式），断网也能演完全流程——这是为比赛现场准备的兜底。
如需接入大模型，复制 `.env.example` 为 `.env` 并填写：

```ini
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-xxxxxx
LLM_MODEL=deepseek-chat
```

也可以填本地 Ollama（`http://127.0.0.1:11434/v1` + `qwen2.5:7b`）。

**安全约束**：API Key 只被后端 `server/config.js` 读取，前端仅通过 `/api/*` 访问业务数据，
密钥永远不会下发到浏览器。若大模型调用失败，系统会自动降级回本地引擎，演示不中断。

## 二、系统架构

```
浏览器（原生 HTML/CSS/JS）
  ├─ 左侧：对话区（Agent 思考过程时间线 + 流式回答）
  └─ 右侧：仿真手机银行（卡片 / 账单 / 理财 / 安全中心）
        │  fetch + SSE(流式)
        ▼
Node.js 零依赖后端  127.0.0.1:8787
  ├─ server/index.js         HTTP 服务 + 静态托管 + SSE
  ├─ server/store.js         状态仓库（内存 + 落盘 + 全程留痕）
  ├─ server/data/mockdata.js 确定性种子生成的沙箱数据
  └─ server/agent/
       ├─ orchestrator.js    编排器：意图 → 规划 → 工具 → 确认 → 反馈（事件流）
       ├─ tools.js           银行工具注册表（含风险等级 / 是否需二次确认）
       ├─ actions.js         动作层：待确认单 / 验证码 / 执行 / 取消（真实扣款只在这里）
       ├─ riskEngine.js      风控规则引擎（10 条规则 + 收款人解析 + 黑名单）
       ├─ billEngine.js      账单分析引擎（统计 / 评分制异常识别 / 订阅自动识别）
       ├─ wealthEngine.js    理财引擎（风险测评 / 适当性 / 推荐对比 / 持仓）
       ├─ giftEngine.js      跨场景联动引擎（对象·日期·预算识别 / 预算内选品 / 送达可行性）
       ├─ localEngine.js     本地意图引擎（离线演示的大脑）
       ├─ nlu.js             中文口语解析（金额 / 时间 / 分类 / 称谓）
       └─ llm.js             大模型网关（OpenAI 兼容，可开关）
```

主要接口：`/api/state`（含待确认单、台账、账单统计、产品库、对话记录）、`/api/chat`（SSE 流式）、
`/api/action/confirm`、`/api/action/cancel`、`/api/actions`、`/api/security`、`/api/audit`、`/api/reset`。

**可观测的 Agent 过程**：每轮对话都会推送
`think → intent → plan → tool_call → tool_result` 事件，前端渲染成时间线，
每步都写清"我在做什么"和"为什么要这么做"，用以体现**真实 Agent 而非普通聊天机器人**。

## 三、功能清单（六大场景 + 一句话指令）

| # | 场景 | 说这一句话 | 能看到什么 |
| --- | --- | --- | --- |
| 1 | 智能转账 | 「给我妈转两千块交物业费」 | 按人名/昵称/手机号尾号找收款人 → 展示收款人/开户行/金额 → 二次确认 → 真实扣款；可说「撤销最近一笔转账」T+0 原路返回 |
| 1 | 定时转账 | 「每月1号给房东转2200房租」 | 生成按月计划（确认后生效） |
| 1 | AA 拆分收款 | 「我们四个人吃饭花了800，跟室友和同学AA」 | 按人数平摊，生成待收明细 |
| 2 | 账单分析 | 「上个月的钱都花哪了？有没有不对劲的？」 | 一句两句：分类占比、环比、时段分布、商户榜；异常识别给风险分与证据 |
| 2 | 年度报告 | 「看一下今年的年度账单」 | 全年收支、月均/日均、最高最低月、分类占比 |
| 3 | 订阅管理 | 「有哪些订阅在扣我钱」 | 已登记订阅 + **从流水自动识别的周期扣费** + 续费倒计时 |
| 3 | 取消订阅 | 「把那个老扣我钱的会员关了」 | 按累计扣费定位到具体订阅（并说明依据）→ 确认 → 不再扣费 |
| 4 | 理财推荐 | 「拿一万块买理财，帮我挑个收益最高的」 | 适当性过滤后的推荐与对比 + **明确屏蔽超等级产品** |
| 4 | 风险测评 | 「帮我做风险测评」 | 5 题问卷 → 算出 C1~C5 并更新可投范围 |
| 4 | 申购/赎回 | 「拿五千块买现金宝」/「把现金宝全部赎回」 | 三道门校验 → 确认（≥¥5000 需验证码，带风险提示朗读）→ 真实扣款/回款 |
| 5 | 卡片申请 | 「我想办一张白金卡」 | 生成受理单（审核中，1–3 个工作日） |
| 5 | 额度调整 | 「把金卡额度提到六万」 | 校验上限与已用额度 → 确认 → 额度与可用同步变化 |
| 5 | 限额/冻结 | 「把信用卡单笔限额降到 5000」/「把这张卡冻结」 | 确认后立即生效，可解冻 |
| 5 | 卡片挂失 | 「我那张白金卡找不到了，先挂失」 | 立即冻结 + 标记已挂失 + 含受理编号的回执 |
| 6 | 跨场景联动 | 「下周我妈生日，帮我安排一下」 | Agent 主动补问 → 锁资金 → 下鲜花+蛋糕 → 生成提醒（全链路一个对话） |
| 7 | **三级权限演示** | 「给我妈转八百块交物业费」/「给我妈转两千块交物业费」 | 前者 🟡 黄色（点击确认）；后者 🔴 红色（分级依据显示“当日累计超过 ¥1,000”，需**短信验证码 + 人脸识别**） |
| 7 | 密码修改 / 解挂 / 虚拟卡（赛题点名） | 「把储蓄卡交易密码改一下」/「把白金卡解挂」/「办张虚拟卡」 | 前两者 🔴 红色多因子；虚拟卡 🟡 黄色即时开通 |

安全侧随时可演：

- 「给陈小雨转两万，尾号7742，有没有风险」→ **已拦截**（陌生收款人 + 整数大额 + 超阈值 + 涉诈黑名单）
- 「帮我看看给我妈转十五万有没有风险」→ **不可执行**（余额不足 + 超单笔/日限额）
- 右侧「安全中心」随时查看：二次确认阈值、风控规则条数、工具注册表、涉诈黑名单、操作日志。

## 五、验收方法

### 5.1 自动化验收

```bash
npm run selftest   # 264 项：全链路（数据/解析/工具/编排/风控/转账/账单/订阅/理财/卡片/跨场景）
npm run verify     # 20 项：真实链路与持久化专项验证（需先 npm start）
```

`npm run selftest` 输出 264 项全部 ✅，覆盖：

1. 模拟数据完整性（3 卡 / 309 账单 / 4 异常 / 5 收款人 / 4 订阅 / 6 理财 / R1~R5 全覆盖 / 用户为 C2）。
2. 中文口语解析（`两千`→2000、`1.5万`→15000、`吃饭`→餐饮分类、`上个月`→时间范围）。
3. 工具执行（`query_balance`、`query_transactions` 正常；未上线工具返回明确"未就绪"而非假装成功）。
4. Agent 完整编排（事件流含 think/intent/plan/tool_call/tool_result、回答含余额、产生界面联动指令）。
5. 意图路由与能力降级（“老扣我钱的会员”正确路由到取消订阅；账单分析降级到交易明细；无关输入不瞎猜）。
6. 异常输入（收款人不存在、无匹配交易、不存在的卡 ID、未知工具名）。
7. 真实链路与持久化（账单统计现算且与总支出交叉校验、意图匹配度由证据推导、对话记录写入仓库）。
8. 全程留痕（成功/未识别/未就绪三类都入库，含原始请求与执行理由）。
9. 风控规则引擎（17 项）：口语收款人解析、涉诈黑名单硬阻断、余额不足差额、超限额、夜间大额、整数大额、诈骗话术；并校验"规则目录 = 实际执行"。
10. 二次确认与取消（9 项）：验证码正确/错误/重放防护、用户取消转 `cancelled` 并留痕、重复取消幂等。
11. 转账风控预检工具（6 项）：真实判定、界面联动、结果落库、审计写入、摘要无写死数字。
12. **阶段 2 转账链路（33 项）**：待确认时余额不变、确认后真实扣款、取消后余额不变、≥¥5,000 强制验证码、错误码/重放防护、撤销原路返回、定时计划、AA 拆分、多待确认单防误操作、对话回「确认」闭环。
13. **阶段 3 账单与订阅（35 项）**：分类合计交叉校验、环比与占比、年度报告一致性、评分制异常识别**独立复现全部预埋异常且误报受控**、订阅自动识别依据、续费倒计时、模糊表述定位取消、取消后金额同步、对话多意图规划。
14. **阶段 4 理财与卡片（42 项）**：测评评分与等级映射、测评过期/缺失拦截、C2→3/3 与 C1→2/4 的适当性变化、**保守型买 R2 被拦**、起购金额与余额不足拒绝、申购扣款与持仓生成、赎回回款、授权拦截写审计、挂失/额度/限额/冻结解冻、办卡受理单状态。
15. **阶段 5 跨场景联动（31 项）**：预算解析不被"一下"干扰、对象/形式识别、日期可行性、预算内最优组合（¥486/留 ¥14）、主动追问、上下文承接、锁定→下单→释放的金额守恒、提醒生成、预算/余额不足拒绝、**悬空草稿不劫持无关提问**。

阶段 2/3/4/5 专项验收（含界面步骤）见 [docs/阶段2-验收清单.md](docs/阶段2-验收清单.md)、[docs/阶段3-验收清单.md](docs/阶段3-验收清单.md)、[docs/阶段4-验收清单.md](docs/阶段4-验收清单.md)、[docs/阶段5-验收清单.md](docs/阶段5-验收清单.md)。

### 5.2 界面验收

1. 启动后右侧顶部显示**储蓄卡可用资金 ¥128,640.35**，卡片区 3 张卡正常渲染。
2. 在左侧输入「储蓄卡还有多少钱」，可看到 Agent 过程时间线逐步展开，随后**流式**输出回答，右侧对应卡片被高亮。
3. 输入「上个月吃饭花了多少」，会调用交易明细工具，右侧列表整批联动显示同一批记录（可点“显示全部”还原）。
4. 输入「给我妈转两千块交物业费」，Agent 正确识别为**智能转账**意图（对应能力在阶段 2 接入）。
5. 点右侧 **「账单」**：分类条形图、月度趋势、异常卡片均为后端对 309 条流水**现算**结果。
6. 点右侧 **「理财」**：6 款真实产品 + 实时适当性计算（会标出 3 款超出 C2 等级）。
7. 点右侧 **「安全中心」**：阈值、黑名单、工具数量、机制现状与审计条数全部来自接口，并如实区分「已生效 / 已就位」。
8. **按 F5 刷新页面**：对话记录与所有数据保留（服务端持久化恢复）。
9. 输入「给我妈转两千块交物业费」：出现**待确认卡片**（收款人/开户行/金额/付款卡），此时余额**不变**；点「确认执行」后 → 右上余额 128,640.35 → **126,640.35**，收到带单号 TR0001 的回执。
10. 输入「给我妈转八千块」：卡片提示**需短信验证码**（沙箱直接显示验证码），输错报错、输对成功。
11. 输入「撤销最近一笔转账」→ 待确认 → 确认后资金原路返回。
12. 输入「给陈小雨转两万，尾号7742，有没有风险」→ **已拦截**，不会出现确认卡片。
13. 输入「每月1号给房东转2200房租」/「我们四个人吃饭花了800，跟室友和同学AA」→ 分别生成定时计划与 AA 待收清单。
14. 点右上「重置演示数据」可一键回到初始态。

## 八、安全设计（全部已落地）

1. **密钥隔离** ✅：API Key 仅存在于后端 `.env`，已全仓检索确认前端零密钥；`.env` 已 gitignore，仓只提交空模板。
2. **沙箱数据** ✅：全部为本地模拟数据，不接任何真实支付/银行接口（界面常驻"沙箱演示环境"标识）。
3. **分级授权底座** ✅：工具注册表对每个工具声明 `risk` 与 `requiresConfirm`，
   配置项 `security.confirmThreshold = 5000` 已就位，审计日志记录是否需二次确认 → 阶段 2 接确认弹窗与模拟短信验证码。
4. **全程留痕** ✅：成功、未就绪、失败、未识别意图四类全部入库，含操作名/风险等级/原始请求/执行理由。
5. **知情同意** ✅：每个工具步骤都有「为什么这么做？」解释入口。
6. **不假装成功** ✅：未实现的工具明确返回"阶段 X 上线"，绝不给出虚假执行结果。
7. **输入防护** ✅：类型/长度（500 字）/请求体（64KB）/控制字符四重校验；静态目录穿越 6 种变体实测均 404。
8. **仅监听本机** ✅：`127.0.0.1:8787`，局域网无法访问；无 CORS 头，默认同源策略。

详细自查结论见 [docs/阶段1-自查清单.md](docs/阶段1-自查清单.md)。

## 九、异常与边界处理

| 场景 | 处理 |
| --- | --- |
| 空输入 / 非字符串 / 非法 JSON | 后端 400 并给出具体原因 |
| 单条消息超 500 字 / 请求体超 64KB | 400 / 413，前端输入框同步限制并显示字数 |
| 收款人不存在 | 返回空结果 + 明确文案，不报错、不编造 |
| 余额不足、用户取消确认 | 属转账路径，阶段 2 实现（拒绝部分扣款、取消后写审计） |
| 意图命中未上线能力 | 能降级则显式降级并说明，否则如实告知阶段 |
| 大模型不可用 / 超时 | 自动降级到本地意图引擎，演示不中断 |
| 前后端断连 | 对话气泡内提示失败原因与重启办法 |

## 十、常见问题

**端口被占用？** 修改 `.env` 中的 `PORT`，或关闭已有实例（启动时会给出明确提示）。

**大模型模式没反应？** 检查 `.env` 三项是否填写完整；服务启动日志会显示当前引擎；
即使大模型不可用，也会自动降级到本地意图引擎并提示。

**数据乱了想重来？** 点界面右上「重置演示数据」，或执行 `npm run reset`。

**输入很长被拒？** 单条消息上限 500 字（防超长文本刷屏与注入），请求体上限 64KB；属预期保护。
