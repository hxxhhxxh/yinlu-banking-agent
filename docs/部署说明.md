# 部署说明

> 本作品为**零第三方依赖**的本地应用：不需要数据库、不需要外网、不需要安装任何 npm 包。
> 目标环境：Windows / macOS / Linux 任一，Node.js ≥ 18 即可。

---

## 一、环境要求

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Node.js | **≥ 18**（开发与验证环境为 v24.19.0） | 需支持内置 `fetch` 与 `ReadableStream` |
| 操作系统 | Windows / macOS / Linux | 已在 Windows 10.0.26200 实测 |
| 磁盘 | 约 5 MB（源码）+ 约 200 KB（运行时状态） | 无外部资源依赖 |
| 网络 | **不需要** | 未配置大模型时完全离线运行 |
| Python | 可选 | 仅用于把 Markdown 文档转换为 Word（非运行依赖） |

## 二、一键部署（本地演示）

```bash
# 1. 进入项目目录
cd yinshu-banking-agent

# 2. 安装依赖（本项目零依赖，此步仅用于生成 lock 文件，秒过）
npm install

# 3. 启动
npm start
```

看到如下输出即启动成功：

```
──────────────────────────────────────────────────────────
  银枢·AI银行副驾  YinShu AI Banking Copilot  v0.1.0
──────────────────────────────────────────────────────────
  服务地址 : http://127.0.0.1:8787
  推理引擎 : 本地意图引擎（离线演示模式）
  沙箱数据 : 3 张卡 / 309 条账单 / 5 个常用收款人 / 4 个订阅 / 6 款理财
  数据模式 : 本地模拟数据，未接入任何真实支付接口
──────────────────────────────────────────────────────────
```

浏览器打开 **http://127.0.0.1:8787** 即可使用。

> 服务**只监听 127.0.0.1**，同局域网的其他设备无法访问——这是刻意的安全设计。

## 四、配置项（可选）

复制 `.env.example` 为 `.env` 后按需修改：

```ini
# 服务端口（默认 8787；被占用时改这里）
PORT=8787

# 大模型（OpenAI 兼容）。全部留空 = 使用本地意图引擎，完全离线
LLM_BASE_URL=
LLM_API_KEY=
LLM_MODEL=
```

| 配置 | 说明 |
| --- | --- |
| `PORT` | 修改监听端口；端口被占用时启动会给出明确提示 |
| `LLM_*` | 配置后自动切换为大模型规划；**任一为空则回退本地意图引擎**；大模型超时或报错会自动降级 |
| `.env` | 已在 `.gitignore` 中，仓库只提交空模板 `.env.example`；**API Key 仅由后端读取，前端零密钥** |

可选：接入本地 Ollama 完全离线使用大模型

```ini
LLM_BASE_URL=http://127.0.0.1:11434/v1
LLM_MODEL=qwen2.5:7b
LLM_API_KEY=ollama
```

## 六、生产化部署建议（从沙箱到行内）

本作品定位是"可演示、可验证的安全参考实现"，若要上生产，按以下顺序改造：

1. **认证与授权**：接入行内统一登录、生物识别与设备指纹；动作层增加操作者身份校验。
2. **数据接入**：把 `data/mockdata.js` 替换为行内账户、账单、产品、订阅与反诈名单接口（引擎接口已抽象，无需改动算法）。
3. **执行通道**：把 `actions.js` 中的本地账本变更替换为行内核心系统/开放平台调用，**确认与留痕逻辑无需改动**。
4. **验证码**：接入行内短信网关，删除沙箱回显逻辑。
5. **持久化**：从单文件状态改为数据库（含事务与幂等键），审计日志接入不可篡改存储。
6. **限流与监控**：增加账号/设备维度的速率限制、异常频次告警与人工复核通道。
7. **模型合规**：如使用大模型，优先接入私有化部署；补充输入输出内容过滤与越权拦截。
8. **部署形态**：可用 PM2 或 systemd 托管，前置 Nginx 反代并设置安全响应头（CSP、X-Frame-Options 等）。


### 本机更新仓库的特别说明

本开发机 **`github.com:443` 不可达**（`git push/pull` 会挂起），但 `api.github.com` 可达，因此仓库内容通过 GitHub API 推送。项目内已附带脚本：

```bash
python scripts/push_via_api.py                 # 全量推送（压缩为单次提交）
python scripts/push_via_api.py --file README.md  # 只更新单个文件（快，走 Contents API）
```

脚本鉴权由 `gh` CLI 提供，**不在代码或参数中传递任何 token**。在能正常访问 GitHub 的机器上，直接 `git push` 即可，无需该脚本。

## 九、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 启动提示"端口已被占用" | 已有实例在运行。关闭它，或修改 `.env` 里的 `PORT` |
| 页面显示"本地意图引擎（离线演示）" | 未配置大模型，属正常容灾形态，功能完全可用 |
| 页面右上出现红色横幅 | 后端未运行或已退出；在项目目录执行 `npm start`，恢复后自动重连 |
| 想恢复初始数据 | 点界面右上「重置演示数据」，或执行 `npm run reset` |
| 输入很长被拒 | 单条消息上限 500 字（防超长文本与注入），请求体上限 64 KB，属预期保护 |
| 刷新后对话没了？ | 不会。对话记录服务端持久化，刷新与重启后自动恢复 |
| 局域网其他电脑打不开 | 设计如此：服务只监听 127.0.0.1。如需演示用局域网访问，请显式修改监听地址（不建议不安全的暴露） |
