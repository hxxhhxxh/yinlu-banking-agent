# 答辩问答预案（银行AI智能体比赛）

> 用法：评委问到时先给**一句话结论**，再给**证据/演示动作**。凡是能当场演示的，优先演示。

---

## 一、安全类（评审重点，优先准备）

**Q1：怎么保证 AI 不会把钱转错、乱转？**
一句话：三道闸——风控规则引擎先判、关键信息必须展示、确认才动钱。
演示：给陈小雨转两万（尾号7742）→ **已拦截**；再说「给我妈转两千块交物业费」→ 卡里余额在**点确认前一分未动**。

**Q2：涉诈黑名单拦截，用户坚持要转怎么办？**
一句话：黑名单是**阻断级**，二次确认也不放行；"陌生收款人"这类是强提醒，可在留痕前提下走验证码延续。
证据：`riskEngine` 判定优先级 `block > reject > confirm > allow`，拦截后的审计 `result = block`。

**Q3：≥5000 为什么必须验证码？沙箱里验证码不是假的吗？**
一句话：模拟的是"第二因素"这一层机制；沙箱直接把验证码显示出来并标注"真实环境由短信下发"，代码里没有回显路径。
证据：验证码 2 分钟有效、错误 3 次锁定、已确认单据**拒绝重放**（都有自测断言）。

**Q4：AI 会不会推荐不适合客户的高风险理财？**
一句话：**先测评、再适当性、才推荐**，不匹配直接拒绝，而且拒绝也留痕。
演示：「拿一万块买理财，帮我挑个收益最高的」→ 明确屏蔽 R3/R4/R5；「申购成长先锋1000块」→ 连确认入口都不给。

**Q5：客户反悔了怎么办？**
一句话：取消与撤销都有明确契约，且都写审计。
证据：取消确认 → `result = cancelled`，文案固定"未发生任何资金变动"；「撤销最近一笔转账」T+0 原路返回（超出当日则明确拒绝并指引柜面）。

**Q6：合规要求"全程留痕"你们做到什么程度？**
一句话：**成功、未就绪、失败、拒绝、取消、未识别意图**六类全部入库，字段含操作名、风险等级、金额、原始请求、执行理由。
演示：点右侧「安全中心」看操作日志。

**Q7：数据脱敏呢？**
证据：接口只输出掩码卡号（`6225 **** **** 6688`）与掩码手机号；`/api/state` 全量响应中检索不到完整卡号/手机号（有断言）。

**Q8：密钥安全？**
一句话：API Key 只在后端读，前端零密钥；不配大模型也能跑（本地意图引擎）。
证据：全仓检索 `public/` 目录无任何密钥字样；服务**只监听 127.0.0.1**，局域网访问不了。

## 二、技术实现类

**Q9：这是真的 Agent，还是规则匹配 + 套壳对话？**
一句话：区别在**过程可见**。每一步都有 `think → intent → plan → tool_call → tool_result`，每步可展开「为什么这么做」，结果全部来自真实工具返回。
证据：时间线 + 「为什么这么做？」按钮 + 工具执行耗时（毫秒级，可见）。

**Q10：用大模型了吗？如果断网怎么办？**
一句话：双引擎。配了 Key 走大模型规划，没配或超时自动降级到**本地意图引擎**——比赛现场断网也能演完。
证据：界面右上徽标会显示当前引擎；本地意图引擎覆盖全部六大场景。

**Q11：数据是真的吗？**
一句话：**沙箱**——309 条账单、3 张卡、5 个收款人、4 个订阅、6 款理财都是本地模拟数据（确定性种子，每次重置完全一致），不接任何真实接口。
证据：界面常驻"沙箱演示环境"标识；`npm run selftest` 输出数据规模断言。

**Q12：刷新会不会丢？重启呢？**
证据：`npm run verify` 专项验证——用**独立进程读磁盘文件**证明落盘；杀进程重启后审计编号连续不重号、对话与台账完整。

**Q13：异常交易识别是真算的还是预埋的？**
一句话：**完全独立复现**。数据里预埋了 4 笔，引擎扫描 303 笔支出后正好识别出这 4 笔，零误报。
证据：右侧「账单」页每笔异常都列出风险分（85/65/60/45）与多条证据；评分规则写在验收清单里。

**Q14：一句"下周我妈生日"怎么就能订花订蛋糕？**
一句话：听懂（对象/日期/预算/形式）→ 缺什么主动问 → 预算内选最优组合 → **锁定资金** → 下单 → 释放剩余 → 建提醒。
证据：¥500 预算下 ¥486 成交并**留 ¥14 当运费**；回执里有"锁定 → 下单 → 释放"完整时序和两个订单号。

## 三、产品与合规类

**Q15：和其他银行的智能客服有什么不一样？**
一句话：客服是"问答"，我们是"**办业务 + 守住边界**"。能真实扣款、能拦截、能撤销，且该拒绝时不含糊。

**Q16：为什么金融场景要"该确认的必确认，不该打扰的不打扰"？**
一句话：全确认会劝退用户，全不确认会出风险。我们按金额与风险特征动态分层：查询直接执行、大额/陌生/夜间/整数强确认、黑名单硬拦。
演示：¥2,000 给常用收款人 → 一次点击确认即可；¥20,000 给陌生账户 → 直接拦截。

**Q17：用户说"老扣我钱的会员"这种模糊表达，AI 会不会关错？**
一句话：会**先说明定位依据**再请确认，定不下来就反问不瞎猜。
证据：「把那个老扣我钱的会员关了」→"我按近期累计扣费最多定位到轻拍云相册（累计 ¥150）"。

**Q18：能落地到真实银行吗？**
一句话：架构上只差数据源与执行通道——风控规则/适当性/确认流程/留痕都已模块化，换成行内名单与核心接口即可。
