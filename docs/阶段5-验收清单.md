# 阶段 5 验收清单：跨场景联动 + UI 打磨 + 异常兜底

> 完成时间：2026-09-22　自测：**selftest 264/264** + **阶段5 HTTP 20/20**
> 阶段目标：一句话「下周我妈生日」→ Agent 主动补问 → 锁定资金 → 自动完成鲜花/蛋糕预订 → 生成提醒，**全链路一个对话完成**。

---

## 一、跨场景联动（本阶段核心）

| 环节 | 实现 |
| --- | --- |
| 听懂 | 识别**对象**（我妈→妈妈/王丽华）、**场合**（生日/母亲节/纪念日…）、**日期**（下周三/9月30日）、**预算**、**形式**（鲜花/蛋糕/都要） |
| 主动补问 | 缺什么就一次问全（日期 + 预算 + 形式），**不逐步骚扰**；信息不全**绝不生成确认单** |
| 上下文承接 | 第二句「下周三，五百左右，花和蛋糕都要」被识别为对上一轮追问的回答（草稿有效期 10 分钟） |
| 预算内选方案 | 在预算内挑**总价最高的鲜花+蛋糕组合**：¥500 → 玫瑰礼盒 ¥268 + 6 寸慕斯 ¥218 = **¥486**，余 **¥14** 预留运费 |
| 锁定资金 | 执行前先**冻结预算**（可用余额扣减 500），下单后**释放未用部分**，不留悬挂锁定 |
| 下单与提醒 | 逐笔真实下单（生成订单号、生活服务流水），并生成**提前一天**的配送确认提醒 |
| 异常兜底 | 预算不够 → 告知最低组合价并请调整；可用余额不足 → 拒绝；日期过近/已过 → 要求改期 |

执行时序（回执里逐字可见）：
`锁定预算 ¥500.00 → 下单 2 笔共 ¥486.00 → 释放剩余 ¥14.00 → 送达 2026-09-30 09:00-12:00 → 生成提醒 2026-09-29`

## 二、UI 打磨

1. **🎁 安排面板**：右侧新增跨场景卡片，实时显示「进行中的安排 / 已完成的安排」、日期/预算/形式、锁定资金、订单明细（类型徽标 + 价格 + 送达时间 + 订单号）。
2. **卡片业务区块**：受理单（卡种 / 受理编号 / 预计出结果时间）在「我的卡」页可见。
3. **持仓区块**：理财页展示持仓、持有天数、估算收益与「赎回」入口。
4. **状态语义区分**：卡片区分「已冻结·原因」与「**已挂失·不可恢复**」。
5. **风险提示朗读**：待确认卡片内嵌 🔊 按钮（浏览器原生 `speechSynthesis`，离线可用）。
6. **连接状态提示**：连续 2 次拉取失败时出现红色横幅，提示后端可能未启动，恢复后自动消失。
7. 交互一致性：所有「确认执行 / 取消 / 赎回 / 撤销 / 取消订阅 / 去确认」入口统一为同一种链接按钮样式。

## 三、异常兜底清单（本阶段新增/补强）

| 场景 | 行为 |
| --- | --- |
| 信息不全（缺日期/预算/形式） | 一次问全，标注"待确认"，不生成确认单 |
| 「下周」太模糊 | **不猜日期**，标记待确认并请用户明确 |
| 「帮我安排一下」的"一" | 不会被当成 ¥1 预算（金额必须带 元/块/左右 等标记） |
| 预算不足 | 告知最低组合价（¥406）并给出替代建议 |
| 可用余额不足 | 拒绝并给出差额，提示可先赎回理财 |
| 日期过近/已过 | 拒绝并说明"需提前 1 天下单" |
| 悬空草稿 | 10 分钟过期；且**只在"没有其他意图命中 + 像在补充信息"时才承接**，不会劫持无关提问 |
| 后端断连 | 前端红色横幅提示 + 自动重连；对话气泡内也会说明失败原因与重启方式 |
| 重复确认 / 重放 | 已执行、已取消、已过期的单据一律拒绝重复提交 |

## 四、验证方法

```bash
npm run selftest   # 264 项（阶段5 共 31 项）
npm run verify     # 20 项
npm start
```

界面验收（已实测）：

1. 说「下周我妈生日，帮我安排一下」→ 右侧出现 🎁「进行中的安排（信息收集中）」，对话里 Agent **主动问**：日期 + 预算 + 形式。
2. 说「下周三，五百左右，花和蛋糕都要」→ 出现「生日安排方案（待你确认）」：日期 2026-09-30 上午送达、预算 ¥500 / 合计 **¥486**、剩余 ¥14，并说明"先锁定资金 → 下单 → 释放剩余"。
3. 点「确认执行」→ 回执写入订单号；右上余额 128,640.35 → **128,154.35**；🎁 面板变为「已完成的安排」并列出两笔订单与送达信息。
4. 按 F5 → 订单、提醒、安排状态全部保留。
5. 说「储蓄卡还有多少钱」→ 不再被生日草稿劫持（安全兜底）。

## 五、本阶段抓出并修掉的 2 个真 bug

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 「下周我妈生日，帮我安排一下」把"一下"的**一**当成 ¥1 预算 | `parseAmount` 兜底匹配了任意中文数字 | 新增 `parseBudget()`：金额必须带 元/块/左右/万/千 等标记，或前有"预算/大概"引导词 |
| 2 | 悬空的生日草稿**劫持后续无关提问**（"储蓄卡还有多少钱"被当成补充信息） | 上下文承接条件过宽（只要草稿存在就接管） | 收紧为：无其他意图命中 + 句子像在补充信息 + 草稿 10 分钟内有效 |
