## 一、理财：适当性管理是真门禁，不是提示语

申购一共过 **三道门**，任何一道不过都不给确认入口：

| 门 | 检查项 | 不通过时的行为 |
| --- | --- | --- |
| ① 测评有效性 | 是否做过测评、是否一年内 | 拒绝并引导「帮我做风险测评」 |
| ② 适当性 | 产品风险等级 ≤ 用户等级（以产品 `suitableFor` 白名单为权威） | **拒绝**并解释，同时写审计 `result=rejected` |
| ③ 起购与余额 | 金额 ≥ 起购线、卡可用余额充足 | 拒绝并给出差额 |

演示用户为 **C2 稳健型** → 可推荐 3 款（R1 货币基金 / R2 固收 / R2 大额存单），**屏蔽 3 款**（R3 混合、R4 股票、R5 权益增强）。
实测「拿一万块买理财，帮我挑个收益最高的」→ 回答里明确写：

> 你问的是"收益最高的"，但我不能顺着推荐：风险等级不匹配的产品，收益再高也不会出现在推荐里。

风险测评：5 题问卷（A–E 各 1–5 分）→ 总分 5–25 → 映射 C1~C5。实测全选 A → C1（推荐瞬间降到 2 款、屏蔽 4 款），全选 E → C5；答案不完整时不硬算，返回问卷。

## 二、申购 / 赎回

| 能力 | 关键点 |
| --- | --- |
| 申购 | ≥¥5,000 需短信验证码；执行层**再校验一次**适当性、起购线、余额；真实扣款并生成持仓与流水 |
| 赎回 | 展示持仓与赎回金额 → 确认 → 资金回到原扣款卡；沙箱按 **T+0 到账（真实环境 T+1，已在回执中标注）** |
| 持仓查询 | 持仓天数、按业绩基准估算的浮动收益（明确标注"估算值，不代表实际回报"） |
| 风险提示朗读 | 待确认卡片内嵌风险揭示文本 + **🔊 朗读风险提示** 按钮，用浏览器原生 `speechSynthesis` 朗读（离线可用，不依赖任何云服务） |

## 三、卡片管理

| 能力 | 关键点 |
| --- | --- |
| 卡片申请 | 确认后生成受理单，状态 **审核中（1–3 个工作日）**——不假装已发卡 |
| 额度调整 | 校验：不超过 ¥200,000 上限、不低于已用额度；变更后**可用额度同步重算** |
| 交易限额 | 单笔 ≤ ¥50,000、日累计不得小于单笔；变更前后值都展示 |
| 冻结 / 解冻 | 冻结即刻生效；**挂失卡不能自助解冻**（提示到柜面补卡） |
| 卡片挂失 | 确认后卡片**立即冻结** + 标记 `lost` + 返回含**受理编号**的回执；不可撤销；重复挂失被拒绝 |

## 四、验证方法

```bash
npm run selftest   # 233 项（阶段4 共 42 项）
npm run verify     # 20 项（真实链路与持久化）
npm start
```

界面验收（已实测）：

1. 输入「拿一万块买理财，帮我挑个收益最高的」→ 推荐表（3 款，含每万元预计年收益）+ 「已按适当性屏蔽 3 款」+ 风险揭示。
2. 输入「申购成长先锋1000块」→ **没有确认卡片**，直接说明"超出你的风险等级，未执行"。
3. 输入「拿五千块买现金宝」→ 待确认卡片：产品/风险等级/业绩基准/扣款卡/**风险提示文本**/沙箱验证码/🔊 朗读按钮。
4. 输错验证码 → 报错；输对 → 执行成功，右上余额 128,640.35 → **123,640.35**，「理财」页出现持仓（可点「赎回」）。
5. 输入「我那张白金卡找不到了，先挂失」→ 待确认 → 确认后卡片变"已挂失·不可恢复"，返回含受理编号的回执。
6. 输入「把金卡额度提到六万」→ 确认后额度 ¥50,000 → **¥60,000**，可用额度同步重算。
7. 按 F5 刷新：持仓、卡片状态、受理单、对话记录全部保留。

## 五、本阶段抓出并修掉的 3 个问题

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 「我想办一张白金卡」不被识别 | 意图词只覆盖"办卡/申请X卡"，漏了"办一张…卡" | 补全口语模式，并加自测 |
| 2 | `/api/state` 无法区分"挂失"与"普通冻结" | `cardSummary` 没输出 `lost` 字段 | 补 `lost/lostAt/frozenReason`，前端显示"已挂失·不可恢复" |
| 3 | 自测结果受线上演示数据影响（第 2 次运行才失败） | 自测读取持久化状态 | 自测开头强制 `reset()` 到演示初始态，断言与现场状态解耦 |
