## 六、修复记录（本轮自查发现并已修掉）

1. **意图误路由**：「把那个老扣我钱的会员关了」原来命中"订阅查询"而非"取消订阅"——调整规则优先级并强化取消类正则。
2. **降级缺失**：「上个月吃饭花了多少」原来落到阶段 3 的"账单分析"直接说未上线——新增**能力降级**机制，先用交易明细给出可用结论并如实标注。
3. **审计不全**：大模型路径不写审计日志；失败/未就绪/未识别意图均不留痕——改为**编排器统一留痕**，覆盖成功/失败/未就绪/未识别四类。
4. **输入无保护**：非字符串、超长（10 万字）、超大请求体均可直达 Agent——已加类型/长度/体量三重校验。
5. **界面联动失效**：交易查询高亮的记录不在右侧"最近 12 笔"里，导致看不见联动——改为把**查询结果整批推送**给右侧面板并附"显示全部"。
6. **渲染缺陷**：回答里的 `>` 提示被原样显示、工具参数里塞满毫秒时间戳——已加提示条渲染与参数美化。

## 九、第三轮自查：安全模块与异常三件套落地（2026-09-22 晚）

> 触发：用户要求"缺的补上再往下走"。本轮把上一版只是"口头承诺"的三类异常处理与风控机制**做成真实代码 + 可验证**。

### 9.1 新增：独立风控规则引擎 `server/agent/riskEngine.js`

| 规则 | 语义 | 判定等级 |
| --- | --- | --- |
| R-09 | 收款人不存在 / 重名歧义 | reject 业务拒绝 |
| R-01 | 收款人不在常用名单 | strong 强提醒 |
| R-02 | 收款账户命中涉诈黑名单 | **block 硬阻断** |
| R-03 | 金额 ≥ ¥5,000 二次确认阈值 | confirm |
| R-04 | 夜间大额（23:00–06:00 且 ≥¥1,000） | confirm |
| R-05 | 整数大额（¥10,000 的整数倍） | confirm |
| R-06 | 可用余额不足（给具体差额） | reject |
| R-07 | 超单笔限额 | reject |
| R-08 | 超当日累计限额 | reject |
| R-10 | 备注命中诈骗话术（刷单/保证金/安全账户/催促…） | strong |

判定优先级：`block > reject > confirm > allow`。规则目录（`RULE_CATALOG`）是规则数量的唯一来源，
自测会校验"对外声明的条数 = 实际执行条数"，**从机制上禁止把规则数量写死**。

### 9.2 三个被点名的异常，现在的真实处理

| 异常 | 现在怎么处理 | 证据 |
| --- | --- | --- |
| **收款人不存在** | 返回 `not_found` + 重名歧义候选，**不编造账户**；判定为 `reject`，并告知"未执行、资金无变动" | 自测：`陈小雨 → not_found`；`150,000 → 拒绝并给出差额` |
| **余额不足** | R-06 给精确差额（可用 ¥128,640.35 / 需 ¥150,000 / 还差 ¥21,359.65），并叠加 R-07/R-08 限额判定，**不做部分扣款** | 自测：命中 R-06 且文案含"还差" |
| **用户取消确认** | 确认票据 `CT000x` 支持 `cancelTicket()`：状态转 `cancelled`，写审计 `result=cancelled`，明确标注"未发生任何资金变动"；重复取消幂等 | 自测：取消→审计 A0000xx result=cancelled |

同时实现了**模拟短信验证码**契约：错误码 → `code_mismatch`；正确码 → 校验通过；已确认票据**拒绝重放**；验证码 2 分钟过期。
沙箱环境下验证码随票据返回并明确标注"沙箱演示"，真实环境应由短信下发、绝不回显。

### 9.3 新增可达能力：转账风控预检（不划转资金）

新增工具 `preview_transfer`，对话示例：

> 「帮我看看给陈小雨转两万，尾号7742，有没有风险」→ 判定 **已拦截**（命中 R-09/R-02/R-03/R-05），右侧弹出风控面板
> 「帮我看看给我妈转两千块有没有风险」→ 判定 **通过**（10 条规则全部通过）
> 「帮我看看给我妈转十五万有没有风险」→ 判定 **不可执行**（R-03/R-05/R-06/R-07/R-08）

预检结果写入 `state.lastPreflight` 并随 `/api/state` 返回——**刷新页面后风控面板仍在**。

边界声明：预检只做**判定与解释**，**不划转任何资金**；真实资金划转与确认弹窗在阶段 2 接入。
