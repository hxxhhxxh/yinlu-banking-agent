# 阶段 2 验收清单：智能转账 + 安全确认与风控模块

> 完成时间：2026-09-22　自测：**selftest 136/136** + **HTTP 端到端 28/28**
> 阶段目标：用户一句话 → Agent 完成『风控预检 → 出示关键信息 → 二次确认（可验证码）→ 真实扣款 → 落台账与流水 → 可撤销』

---

## 一、本阶段交付（全部为真实链路）

| 能力 | 实现方式 | 关键点 |
| --- | --- | --- |
| 智能转账 `transfer_money` | 真实扣减卡片余额 + 写流水 + 记转账台账 | 按人名/昵称/手机号尾号模糊找收款人；**未确认绝不扣款** |
| 定时转账 `schedule_transfer` | 生成按月/一次性计划 `plans` | 「每月1号给房东转2200」可正确解析为周期性 |
| AA 拆分收款 `split_aa_collect` | 生成待收明细 `aaSplits` | 缺参与人时**反问用户**，不瞎猜 |
| 撤销最近一笔转账 `undo_last_transfer` | 资金原路返回 + 原记录标 `reversed` + 反向流水 | 仅限当日（T+0），超出则明确拒绝 |
| 转账台账查询 `query_transfers` | 只读 | 展示时间/收款人/金额/状态 |
| 待确认单机制 | `pendingActions` + 票据 + 验证码 + 取消 | 支持对话回「确认」或界面点按钮两种方式 |
| 分级授权落地 | 低于阈值点击确认；**≥¥5,000 或命中风控强制短信验证码** | 验证码 2 分钟有效、错误最多 3 次、防重放 |
| 风控接入 | 复用阶段 1 的 `riskEngine`（10 条规则） | block/reject **不生成待确认单**，不给确认入口 |

## 二、安全设计（本阶段最关键的部分）

1. **预检先于执行**：创建待确认单时先跑 10 条风控规则；`block`（涉诈黑名单）与 `reject`（收款人不存在/余额不足/超限额）**直接不给确认入口**。
2. **关键信息前置**：待确认卡片必须展示 **收款人 + 开户行 + 脱敏账号 + 金额 + 付款卡 + 命中规则**，用户看清楚才可能确认。
3. **未确认零变动**：自测专门断言"生成待确认单时余额不变"、"取消后余额完全不变"。
4. **执行时二次校验**（防并发/超时/状态变化）：真正扣款前重新校验卡状态、可用余额、单笔限额；失败则落 `failed` 审计且明确"未发生资金变动"。
5. **防重放**：已执行/已取消/已过期的单据拒绝重复提交（自测覆盖）。
6. **防误操作**：同时存在多个待确认单时，回复「确认」会**反问用户确认哪一单**，并断言此时余额不变；支持「取消 PA0002」精确取消指定单。
7. **取消留痕**：取消写审计 `result = cancelled`，文案固定包含"未发生任何资金变动"。
8. **验证码安全语义**：沙箱环境验证码随票据返回并**明确标注"沙箱演示"**；真实环境应由短信下发、绝不回显（代码注释已声明）。
9. **超时保护**：待确认单 2 分钟失效，超时自动转 `expired` 并留痕。

## 四、验证方法

```bash
npm run selftest        # 136 项（含阶段2 共 33 项：扣款/确认/取消/撤销/定时/AA/多单防误操作）
npm run verify          # 20 项（真实链路与持久化）
npm start               # 启动后按下面「界面验收」手测
```

界面验收（已实测通过）：

1. 输入「给我妈转两千块交物业费」→ 左侧出现**待确认卡片**（收款人/开户行/金额/付款卡），右侧出现黄色**待确认横幅**，此时右上余额**不变**。
2. 点卡片里的「确认执行」→ 余额从 ¥128,640.35 → **¥126,640.35**，返回带转账单号 TR0001 的回执，"最近转账"出现该笔并带「撤销」按钮。
3. 点「撤销」→ Agent 走一次待确认 → 确认后资金原路返回。
4. 输入「给我妈转八千块」→ 卡片提示**需短信验证码**，卡片内直接显示沙箱验证码；输错 → 报错并给剩余次数；输对 → 执行成功，台账 `确认方式=短信验证码`。
5. 输入「给陈小雨转两万，尾号7742，有没有风险」→ **已拦截**，不出现确认卡片。
6. 输入「每月1号给房东转2200房租」→ 待确认 → 确认后写入计划。
7. 输入「我们四个人吃饭花了800，跟室友和同学AA」→ 待确认 → 确认后生成每人 ¥200 的待收清单。
8. 按 **F5 刷新**：待确认单、转账台账、对话记录全部保留。

## 五、本阶段抓出并修掉的 4 个真 bug

| # | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| 1 | 确认接口 500 | `/api/action/confirm` 里 `const res = actions.executeAction(...)` **覆盖了 HTTP 响应对象** | 重命名为 `result` |
| 2 | 「撤销最近一笔转账」被当成普通转账 | 意图规则顺序问题（`transfer_money` 的 `/转账/` 先命中） | 撤销规则提到转账规则之前 |
| 3 | 「每月1号给房东转2200」被解析成一次性转账、金额算成 ¥1 | ①`parseAmount` 把"1号"当金额 ②`parseDate` 的周期性分支排在通用 `[日号]` 之后 | 解析前先剔除日期/人数/账号类数字；周期性日期优先判断 |
| 4 | 「4个人吃饭花了800」金额可能被算成 4 | 同上（人数被当金额） | 同上，并补 2 项自测卡死 |
